# 已知差异裁决：老引擎（轻阅）vs 新引擎（legado-engine）

> ⭐ **这份文档的用途**：把「老引擎的规则转移到新引擎」这件事里的**每一处不一致**都记下来、写清理由。
> ⇒ 白名单：`conformance/fixtures/known-legacy-divergences.json`
> ⇒ 门禁：`Tests/LegadoCoreTests/LegacyDivergenceGuardTests.swift`
> （**白名单外的差异 = 回归 ⇒ 门禁红**；修好了就清白名单 ⇒ 白名单不许腐烂）⭐⭐⭐

## 判据（先立规矩，再看个案）

| 角色 | 定位 |
|---|---|
| **Legado（安卓原版）规格** | **权威** ⇒ 新引擎照它实现 |
| 轻阅老引擎（`reference/js/`） | **参考实现 / 被对照方** ⇒ 用它验行为，**但它自己会错** |
| 站方真实书源（125 源包） | **事实** ⇒ 写法兼容的硬约束 |

⇒ 所以「不一致」的判法只有一条：**老引擎的行为 ≠ Legado 规格时，服从规格**（站方真在用的写法更是硬约束）⭐⭐⭐
⇒ **不是**「老引擎说什么就抄什么」—— 抄老引擎的 bug = 把 bug 复制到新引擎 ⭐

## 一、19 条已知差异（全部 = 老引擎的债，**有意不照抄**）

### ① 链段裸标签名 `@li` ⇒ 老引擎当「属性」取（15 条）⭐⭐⭐

**涉及**：`chain-01/02/03/04/05/06/20/22/30`、`dom-01/05/06`、`sel-08b/10/14`

**老引擎实际行为**（2026-10-25 实测，`reference/js` + jsdom）：

```
QR.dom.selectAll(doc, 'class.catalog_ls@li')  ⇒ ['第一章第二章']   ← 整个 ul 的文本，一个元素
QR.rule.evalOne('class.catalog_ls@li', …)    ⇒ []                 ← 真实求值路径：取不到子元素
```

⇒ 老引擎把 `@li` 理解成「取 `li` 属性」⇒ **子元素选择器不生效**。

**为什么必须不照抄**：

- 站方 125 源里 **`@li` 出现 123 处**（另有 `@p` 117 / `@span` 111）⇒ 这是**站方主流写法** ⭐
- 真实用例：神马小说 `ruleToc.chapterList = "class.catalog_ls@li"` ⇒ 照抄 ⇒ **轻阅上该源目录是空的** ⭐⭐⭐
- Legado（安卓原版）支持这种链段写法 ⇒ **新引擎 = 安卓行为 = 跨端一致** ⇒ 照抄老引擎反而变成「只有轻阅坏」⭐

⇒ **裁决**：新引擎按 Legado 规格（`@li` ⇒ 子元素选择器）。**不照抄。**

### ② 换行多规则 ⇒ 老引擎只返回第一行（1 条：`fbk-04`）

- 站方的「多规则」写法是**换行**（`tag.h1@text\ntag.h2@text`）⇒ 列表出口应**合并**。
- 老引擎只返第一行 ⇒ **债**。
⇒ **裁决**：不照抄（新引擎合并）。

### ③ JSON 单值路径命中对象 ⇒ 老引擎丢结构（2 条：`json-03/04`）

- 期望：`$.item` 命中对象 ⇒ 原样保留 `{"title":"章节名","url":"u1"}`。
- 老引擎给出 `"\tu1"`（结构丢失）⇒ 明显 bug。
⇒ **裁决**：不照抄。

### ④ 纯 JS 的 `result` ⇒ 老引擎是节点不是 JSON 视图（1 条：`jsp-04`）

- `@js:result.bid` ⇒ 老引擎取不到（条目级 `result` 是 DOM 节点）。
- 新引擎按规格给 JSON 视图 ⇒ **更宽松**（不会让站方失败）。
⇒ **裁决**：不照抄（保持更宽松）。

## 二、曾经踩过的坑：差异**不是**老引擎的错，是**接线漏了**

### `put-01`（`@get:{k}` 取不到变量）—— 2026-10-25 修 ⭐⭐⭐

- 症状：老引擎 `@get:{xid}` 返回空 ⇒ 一度被当成「老引擎的债」。
- **真因**：老引擎的 `@get:` / `@put:` 走 **`QR.runtime.vars`**（`rule-analyzer.js` 的 `applyGetPut`）
  ⇒ 而对拍 harness 只把夹具的 `ctx.vars` 放进 `ctx`，**没灌进 `QR.runtime.vars`** ⇒ **是 harness 接线漏了** ⭐
- 修法：`conformance/js-runner.js` 里每个用例前把 `ctx.vars` 灌进 `QR.runtime.vars`（**没改只读的老引擎参考实现**）。
- ⇒ 修完：`put-01` 转绿，差异 20 → 19。
- ⇒ **元教训**⭐⭐⭐：**看到「老引擎不对」先问「我的夹具/接线对不对」** ——
  否则会把**自己的 bug** 记成**别人的债** ⇒ 白名单里就多一条假账 ⇒ 以后真回归了也被淹没 ⭐

## 三、这份清单的纪律

1. **白名单只进「有意不一致」**，且每条必须写 `semantic` + `reason` ⇒ 不许「以后再说」⭐
2. **白名单外的差异 = 回归** ⇒ 门禁红 ⭐
3. **修好了要清白名单** ⇒ 门禁会查「白名单里有没有已经一致的 id」⇒ 白名单不许腐烂 ⭐
4. 跑不动 JS 侧（缺 node/jsdom）⇒ **显式 skip**，**不许**把 skip 说成「全绿」⭐⭐⭐
5. 新增差异时：**先查是不是自己的夹具/接线问题**（见第二节）⇒ 再判是不是老引擎的债
